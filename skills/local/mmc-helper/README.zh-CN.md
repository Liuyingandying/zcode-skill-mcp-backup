## 为什么想到做这个

从入学后便开始接触数学建模竞赛，我参与，是被它能从实际问题中提取数学模型，并尝试通过算法以及模型精确程度去刻画每一个问题的求解，意图寻找最佳解法的能力所吸引。

而每次参赛阅读题目都能发现每道题都有很强的**可落地性**——与先前初中高中的题目不同，这些离现实世界里的问题越来越近，在每次思考解题时都有很强烈的激动感——我或许真的站在了某个当下的工程师身边，去思考这些问题的可行性解法。

一开始参与比赛，由于我不是计算机相关专业的学生，而当时的生成式ai也就只能为我（可能是当时的我不会写提示词以及接触最前沿的操作方式）检查代码问题，以及告知我word的排版可以怎么调。

可随着时代的日新月异以及更多专业的名词逐渐被大众熟知，我的脑海里便开始思考，如果我也能尝试学会写skill，让智能体能成为一个数模比赛的协助手：帮助我们一起思考数模的题目、一起参与寻找建模方向、一起构建程序并能及时检查出问题、一起核对并能帮忙调整修改论文格式以及可以优化的细节……

说干就干，因此这个skill应运而生。

## 他能解决什么问题

在我的视角下，数学建模竞赛的时间压力主要来自三处：**建模方向反复、代码与模型脱节、论文写作返工**。
因此，mmc-helper 考虑用三个方案去应对：

### **多阶段状态机**

整个数学建模比赛的流程其实是固定的。

> 确立选题 → 查找文献寻找建模以及算法解决方案 → 汇总开始解题 → 完成模型建立 → 编写算法完成结果处理 → 论文写作收尾

所以我考虑是不是可以用skill将整个流程进行固定，作为一个严格的流程，这样既可以起到监督作用以及分部分的着重攻坚解决当前阶段的任务，基于此，我为skill确立了如下流程：

> 立项 → 确立协作模式 → 用户形象描绘与背景资料提供 → 题目剖析与文献集结 → 分角色攻坚 → 汇总收尾

每个阶段严格设立了闸门，只有用户同意继续后才允许进入下一段的步骤，全流程透明且能及时向用户展示各阶段结果。

### **多角色协作**

如同数模比赛中会有三个人进行分工协作完成题目，本skill也分别设立了分工，不过基于此三"人"还增加了一位新的队员：**建模手 / 编程手 / 论文手 / 审核手**

这各个队员可以考虑使用子智能体，也可以按照 *建模--编程--论文* 的步骤进行项目推进，此外审核手则是脱离主流程之外的队员，他仅负责检查审核整体思路并进行纠偏纠错。主流程中的队员交接严格按照闸门进行，并且进行切换必须等待用户意见。

### **强协议层**

在进行测试中，还是发现了各种各样的问题，基于多次测试以及我对整个skill的构想，提出了如下的强协议要求：**强锚定、启动自检、审核、交接留痕、批量意见处理，把"遵守流程"从依赖记忆变成依赖机制**。

## 安装

本仓库本身就是技能本体。安装两步：

1. clone 或下载本仓库，得到一个名为 `mmc-helper/` 的目录
   （目录名已与 `SKILL.md` 中的 `name` 字段一致，无需改名），把它放进你的 skills 目录；
2. 重启或重新加载技能列表，确认已加载。

安装后的目录应形如：

```
<skills 目录>/
└── mmc-helper/
    ├── SKILL.md          ← 技能入口（加载器只读这一份）
    ├── agents/ protocols/ references/ templates/
    ├── examples/ paper-library/
    └── INDEX.md  CHANGELOG.md  README.md
```

> 说明：除 `SKILL.md` 之外的文档都是给人和智能体阅读的参考资料，**不影响技能加载**。

## 设计要点

- **强锚定**：skill 激活后在用户明确结束前持续生效，抗上下文压缩（`protocols/anchoring.md`）；
- **可校验状态**：`state.json` 记录产物、生效参数、作废项与待决项，新会话先跑启动自检（`protocols/startup_verify.md`）；
- **独立审核**：审核手只质疑不生产、可读题目但不深度了解项目过程，并做**交叉审查**（"此前各问的缺陷本问是否重犯"）；
- **写作范式库**：把"该怎么说"沉淀成可迁移的范式（`references/style_patterns.md`），而非只列禁用词；
- **已知坑清单**：18 条常见缺陷，每条附"如何检出"（`references/known_pitfalls.md`）。

## 我的想法

其实现在的数学建模比赛逐渐脱离了原有的方向，这并不是大家所期望看到的，即AI**逐渐将**成为写出优秀作品的 *必需品* ：最近的比赛，众多论坛里都在讨论如何如何用AI如何用agent如何用skill可以几乎完美的写出一份优质思路或者一份优质作文。

**我并不是反对使用AI**，我只是更担心的是，如果AI接手的程度越来越高，而作为使用者的用户所掌握的知识并不能赶上AI，那么随着每一次题目因需要对抗AI出的越来越难，作为普通者的用户该如何去辨别所有的产出是否正确以及合理，以及如何让AI参与协助的每一次比赛既是一次训练也是一次学习。

上述这一个思考，也是我在这个skill里无比强调留痕以及最后生成学习建议报告的原因。AI在向前进步，作为使用者的我们，也要努力跟上他们的步伐，去尝试做到AI的每一次生成都能去用自己的知识以及所学进行判断是否是正确的。
