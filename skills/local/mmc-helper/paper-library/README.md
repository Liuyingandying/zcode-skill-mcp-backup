# 获奖论文学习库

> mmc-helper 内置的**获奖论文学习库**：把公开的竞赛获奖论文逐篇读成**精炼笔记**，
> 供论文手在写作对齐时参照其**结构、写法与格式**。
>
> **只借写法与结构，不搬内容与结论。**

---

## 一、目录结构

```
paper-library/
├── notes/
│ ├── 2023/ 每篇一份精炼笔记
│ └── 2024/
└── deep-reads/ 与某道真题同题的三篇深读笔记
```

**笔记体例**：每篇八项——一句话定位 / 结构提纲 / 摘要写法 / 逐问组织 / 图表体例 /
写作与表达特色 / 格式观察 / 可借鉴点与不要学点。

> 本库收录的是**阅读笔记**，不包含论文原文。

## 三、使用方法

### 读两次（硬要求）

1. **项目立项时读一次**——建立整体印象：这类题目通常怎么写、结构长什么样；
2. **正文动笔前再读一次**——把写法落到**具体章节**上：这一章该怎么起、结果该怎么报。

**第二次不可省**——立项时的印象容易被长上下文冲毁。

### 选篇顺序

1. **同题优先**：若库中有与本题同题的篇目 → 先读 `deep-reads/`；
2. **同题型次之**：按题型找相近篇——
 - A 类（机理 / 几何）→ 建模推导与图示；
 - B 类（运筹 / 决策）→ 决策变量、约束与算法证据；
 - C 类（数据 / 统计）→ 数据预处理、指标选择与结果解读；
3. **只学结构、写法、图表与论证方式**；方法与数值结论**一律不搬**。

## 四、跨篇吸收要点（可当作"获奖写法均值"）

> 逐篇的具体证据见各笔记；此处只给跨篇一致的高频结论。

### 普遍做对的（值得模仿）

1. **摘要**：一页内按问分节，每节带 1–3 个**可复核数值**与完整口径，末段给"发现型"结论句；
 多数**没有**"本文亮点"式自夸段；
2. **问题分析先行"翻译"**：把每问翻译成"模型类型 + 决策变量/目标/约束"或"方法链"，
 先给读者地图再展开；
3. **每问固定闭环**：建模思路 → 模型建立 → 求解 → 结果分析（表/图紧跟 + 文字解读）→ 检验/小结；
 跨问**显式复用前问模型**（把前问当子程序）；
4. **主动点破题目的"坑"**并给规避口径，把坑写成加分判断点；
5. **数值可信度三件套**：双算法/双解法交叉验证 + 误差表 + 参数灵敏度；
 稳健性尽量独立成节，结论按"**决策是否变 → 数值变多少 → 形态是否变**"三层写；
6. **决策/优化题**：0/1 决策向量统一编码 + 位串（或方案编号）表 + 逐条文字翻译一一对应 +
 全枚举打分标最优（或收敛证据图）；
7. **结果与交付物一一对应**，并在摘要点明表号；对结果给出解读（把系数翻译成业务判断）。

### 普遍翻车的（正好是评审红线）

1. **能编译 ≠ 排版合格**：题注格式不统一、编号重复或乱序、图号与正文引用错位、
 关键词连排——**交稿前必须逐图逐表 + 渲染抽查**；
2. **结构不齐**：有的把每问做成顶层章；有的缺独立的"模型的分析与检验"；
 有的"改进与推广"有标题无内容、评价只写优点，或独缺某一问——**先按官方模板折算层级再学结构**；
3. **参考文献偏薄/偏弱**：数量少、方法出处与体系不匹配、用新闻或公众号链接充数、
 条目要素残缺——引用数量与规范性是稳定扣分点；
4. **附录过大**：多个案例的附录占全文 1/4 到 1/2——附录应精选核心代码并说明运行环境，
 支撑材料另包；
5. **小标题过碎或空壳小节**；"结果分析"只陈列表格缺解读；
 启发式算法无收敛证据或与穷举最优对照——**这些都会被直接扣分**；
6. **数字细节不自洽**：摘要单位与正文不一致、口径与题面不一致——交稿前做一次"数字互查"。
