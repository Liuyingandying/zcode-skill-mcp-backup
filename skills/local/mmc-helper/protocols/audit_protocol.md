# 协议 · 审核

> 配套角色卡：`agents/auditor_agent.md`

---

## 一、隔离方式

**推荐做法**：用**干净上下文的子智能体**承担审核手，通过**产物白名单投递**实现隔离。
（若所用平台不支持子智能体，直接采用下文的同会话降级方案。）

```
主流程                                 审核手（干净上下文）
  │                                        │
  ├─ 导出 audit_package/  ──────────────▶  │  只读该目录
  │    · 题目原文                          │
  │    · 模型规格书                        │
  │    · 结果文件                          │
  │    · 验收清单（三张清单）               │
  │    · known_issues.md（历史缺陷累积）    │
  │                                        │
  ◀──────────── audit/第N问_审核意见.md ───┤
```

**关键点**：审核手**拿到题目、拿到产物、拿不到对话史**——读得到"要解决什么"，
读不到"我们是怎么一步步做出来的"，从而避免被项目过程同化。

**次选做法**（无法开子智能体时）：同一会话内切换 persona，**只允许读 `audit_package/`**，
并在报告中声明"本次为同会话审核，独立性弱于子智能体"。

## 二、触发与闸门

| 触发点 | 时机 | 未通过时 |
|---|---|---|
| T1 | 模型规格书定稿后（编码前） | 不得开始编码 |
| T2 | 结果文件产出后 | 不得进入论文写作 |
| T3 | 收尾前（全篇） | 不得提交 |

## 三、审核报告结构

```markdown
# 第 N 问 · 审核意见

## 一、审查范围与依据
（读了哪些文件；本问的建模对象一句话概述）

## 二、信息时序与因果性
| # | 发现 | 依据（可复现） | 严重度 | 建议 |
## 三、对照实验三要素
## 四、参数与物理范围
## 五、交付文档可读性
（不看代码能否读懂？现行与作废是否分离？用户此前整改要求是否执行？）

## 六、历史缺陷重犯检查
| 历史缺陷 | 本问是否重犯 | 证据 |
## 七、结论
（通过 / 有条件通过 / 不通过）
```

---

## 四、辩论与留痕

1. 建模手／编程手在报告末尾追加「**应答**」章节，逐条写"接受 / 反驳 + 依据"；
2. 用户仲裁；
3. **争议未采纳的条目连同双方立场一起留在留痕中**——不得删除审核意见；
4. 已确认的缺陷写入 `audit/known_issues.md`，作为后续各问的**交叉审查清单**。

---

## 五、与"三查两证"的关系

- **三查两证**（见 `protocols/quality_control_protocol.md`）查的是**文献与资料的真实性**；
- **本协议**查的是**模型与交付物的有效性**。

两者互补，**不可相互替代**：文献全部真实，模型仍可能用错信息；
计算全部正确，文档仍可能无法被人理解。
