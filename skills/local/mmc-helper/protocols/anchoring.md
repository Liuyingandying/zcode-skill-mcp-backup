# 协议 · Skill 强锚定

> **本协议解决的核心问题**：长会话中，上下文压缩（compaction）、跨会话交接、以及大量工具调用，
> 都会让智能体**逐渐忘记自己正处在 skill 流程中**——表现为：跳过阶段闸门、不再请示用户、
> 忘记角色边界、把 skill 的规范抛在脑后。
>
> **本协议是强制性条款，优先级高于本 skill 内其它所有说明。**

---

## 一、锚定条款（必须遵守）

### 1.1 生效条件
用户消息中**出现下列任一情形**，本 skill 即被激活：
- 直接点名 skill（如"用 mmc-helper""加载 mmc-helper""调用 mmc-helper skill"）；
- 说出触发词（数学建模、建模比赛、建模竞赛、CUMCM、国赛、美赛、MCM、ICM、研究生建模、校赛、
  帮我建模、建模手、编程手、论文手、审核手、写建模论文、建模摘要）；
- 用户在本 skill 已激活的会话中继续对话。

### 1.2 生效期：**直到用户明确表示结束**
一旦激活，**在收到用户的明确结束信号之前，本 skill 始终保持生效**，具体含义：

| 情形 | 是否仍受本 skill 约束 |
|---|---|
| 用户连续多轮都在做具体工作（改论文、调代码、算结果） | **是**——工作就是在 skill 流程内推进 |
| 上下文被压缩 / 摘要替换 | **是**——锚定不因压缩而失效 |
| 会话被交接给新对话 | **是**——新对话开工第一步先读交接文档与本协议 |
| 用户切换到闲聊或无关话题 | 视情况：若明显脱离竞赛项目，可暂不适用；一旦回到项目即恢复 |
| 用户长时间未提及 skill | **是**——沉默不等于结束 |

**"明确结束信号"仅包括**（用户须主动说出其一）：
> 「结束 skill」「退出 skill」「不用 skill 了」「这个项目做完了，正常聊」「停用 mmc-helper」
> 等**内容明确表示不再使用本 skill** 的表述。

**下列情形不构成结束信号**：
- 用户只是换了个话题、没提 skill；
- 上下文被压缩；
- 开了一个新对话；
- 用户说了"先这样""可以了""继续"（这是推进指令，不是结束指令）。

### 1.3 锚定动作（每次响应都要自检）

在**每一轮**响应用户之前，做一次三问自检：

1. **我现在在 skill 的哪个阶段、哪个角色？**（Phase 0–3 / 建模手·编程手·论文手·审核手）
2. **这一步该遵循哪条协议？**（阶段闸门 / 交接 / 审核 / 批量意见；见 `INDEX.md`）
3. **我有没有因为上下文变长而偏离规范？**（是否跳过请示、是否忘了留窗口、是否越权改文件）

自检结论**不需要向用户复述**，但如果发现偏离，**必须先纠正再继续**。

### 1.4 抗压缩条款（关键）

上下文压缩后，**摘要里可能不含 skill 状态**。因此：

- 每次进入新阶段或改角色时，**把当前状态写进 `_mmc_internal/state.json` 与 `MMC_Journal.md`**
  （不要只留在对话里）——这是抗压缩的唯一可靠手段；
- 上下文一旦被压缩或交接，**恢复工作的第一步是读 `state.json` 与交接文档**，而不是凭印象继续；
- **禁止**因为"记不清了"就自行简化流程或跳过闸门；宁可停下来重新读文档。

### 1.5 强制自我声明（低成本、高收益）

在本 skill 激活期间，**每次进入一个新阶段、或每完成一个较大步骤时**，用一句话向用户表明仍在流程内，
例如：
> 「当前 Phase 2 · 论文手 · 正在做第 3 章的写作计划」

这一句话让用户随时可以判断智能体有没有跑偏——**这不是客套，是锚定的一部分**。

---

## 二、锚定为何必要（设计说明）

- 长会话的**上下文压缩**会丢掉流程状态：一次摘要就可能让"每步请示用户"的约定消失；
- **跨会话交接**依赖文档，而文档需要被主动读取——没有锚定条款，新会话容易直接开工；
- **多角色切换**（建模手/编程手/论文手/审核手）本身容易让智能体忘记当前角色的边界；
- 用户的**信任来自可预期性**：如果智能体时不时忘记约定，用户就不得不反复重申规则，
  协作成本急剧上升。

**结论**：锚定不是形式条款，而是**把"遵守流程"从依赖记忆变成依赖机制**。
