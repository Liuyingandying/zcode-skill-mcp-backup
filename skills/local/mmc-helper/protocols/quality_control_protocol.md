# 三查两证 · 质量监督协议

> 用途：mmc-helper 全流程的质量监督机制，用于抑制三类高风险问题——
> **① 思路固化 ② 文献幻觉 ③ 文献不贴合**，并延伸覆盖**编程阶段异常**与**证据误写**。
> 对应四阶段状态机中 Phase 1（强制）、Phase 2（编程监看）、Phase 3（收尾延续）。

---

## 0. 总览

**三查**（查方向对不对、查材料真不真、查文献贴不贴）：
- **查真实** —— 反幻觉，保证引用与数据真实存在。
- **查贴合** —— 反不贴合，保证每条文献都实际服务于某个子问题/方法。
- **查思路** —— 反固化，保证方向开阔、可被反驳、可重开。

**两证**（证据分级、可行性试点验证）：
- **证据分级** —— 别把"推断"写成"实测/已验证"。
- **可行性试点验证** —— 只在候选优劣难分时，跑最小实验证明确实可行。

> 执行原则：**三查是"每阶段必过的门"，两证的"证据分级"是"必做"，"可行性试点验证"是"严格准入的特权"。**
> 各查/证的判定结果要写回 `_mmc_internal/state.json` 的 `lit_verification` / `pending_gates` 字段，保证可追溯、可恢复。

---

## 1. 三查

### 1.1 查真实（真实性凭证 / 反幻觉）

**目标**：杜绝编造引用、编造数据、编造"某文献的结论"，并**避免把低可信来源当权威**。

**硬规则**：
1. **凡引用必带可验证标识**：真实 URL / DOI / 标题 / 作者 / 年份，至少满足其一且能被解析。
2. **未验证来源只标"疑似 / 待验证"**，**绝不作为事实引用**；不得进入正文 `\cite{}`。
3. **禁止编造任何数值**：R²、样本量、p 值、某文献声称的"结果"——都必须来自实际可查证的来源。
4. **禁止**虚构作者、期刊、卷期、页码、会议名。
5. **来源与佐证**：
   - 只引用**经典 / 同行评审 / 权威**来源作为定论依据；博客、百科、论坛、无评审预印本、未署名文章**只作参考线索，绝不作为唯一依据**。
   - **优先引用一手原始文献**；若引用综述/二手转述，需上溯到原始论文，转述只在无法获取原文时作为次选并注明。
   - **时效性提醒（advisory）**：若某方法已有较新且公认更优的变体，注明"有更新方法，此处采用经典做法（原因）"，避免看起来在用过时方法。

**验证手段**（按需选用）：
- 用**联网检索**定位真实文献页（有无该能力及降级路径见 `references/tool_and_env_guide.md` 第二节）。
- Crossref / Semantic Scholar API 解析 DOI 或标题，校验元数据（作者/年份/期刊）。
- 若无法验证 → 标记 `pending`，进入"待用户复核/待用户提供"清单，**而不是**当成已确认。

**触发时机**：每个来源进入文献矩阵**之前**。

**产出**：`01_题目剖析/文献真实性复核.md` —— 列出每条引用 + 可验证标识 + 验证状态（verified / unverified / pending）+ 可信度评级（authoritative / secondary / reference-only）。（留痕文体见 `templates/README.md`：正文用清楚叙述，表格只用于"引用标识对照"。）

**严格度**：Phase 1 闭合时，**任一引用为 unverified 但仍被纳入"事实引用" = 强制阻断**，不得进入 Phase 2。

---

### 1.2 查贴合（贴合度过滤 / 反不贴合）

**目标**：避免堆砌"看起来很相关但帮不上忙"的文献，确保检索结果真正服务于解题。

**硬规则**：
1. 每条保留文献必须**明确映射到某个具体子问题或方法**；无映射则**剔除**。
2. 给每条保留文献打**贴合度评分**：`High`（直接给该方法/模型）、`Medium`（提供可迁移思路/变体）、`Low`（背景/方法综述，可留作引言）——**Low 只能作背景，不得作为建模依据**。
3. 文献矩阵表中的每一行都要能回答：**"它解决了哪个子问题的哪个环节？"**

**触发时机**：文献矩阵建成时、Phase 1 闭合前；Phase 2 建模手选型时复核一次。

**产出**：`02_文献资料/文献矩阵.md`（文献 ↔ 子问题 ↔ 提供模型/方法 ↔ 贴合度评分），作为后续建模手与论文手的直接依据。

**严格度**：**存在未映射到任何子问题的保留文献 = 提示剔除**；若用户坚持保留，需注明用途（如引言背景）。

---

### 1.3 查思路（思路开放性 / 反固化）

**目标**：避免"选定一个方向就一条路走到黑"，确保方向开阔、可被反驳、可随证据重开。

**硬规则**：
1. **候选方向必须来自 ≥2 个不同方法族**（统计 / 机器学习 / 机理 / 图论 / 优化 / 差分方程…），**不允许**都是同一思路的不同参数微调。
2. 方向确认前，强制生成**反驳清单（counter-argument list）**：
   - 该思路在什么条件/数据下会失败或崩坏？
   - 相比其它候选，它的最大短板是什么？
   - 若被否决，退路是什么？
3. **方向确认是"检查点"，不是"死锁"**：任何阶段出现新反证（如 Phase 2 结果异常、数据与假设不符），允许**重开方向**重新评估，新增证据可推翻早先决议。

**方法族划分**（供查思路判"是否 ≥2 族"参考）：
| 族 | 代表方法 |
| --- | --- |
| 评价 | AHP / TOPSIS / DEA / 熵权法 / 模糊综合 / 主成分 |
| 优化 | 规划 / 进化算法 / 多目标 |
| 预测 | 时间序列 / 回归 / 机器学习 / LSTM / GM(1,1) / 微分方程 |
| 统计·分类 | 聚类 / 因子·判别 / SVM / 决策树 |
| 图论·网络 | 最短路径 / 网络流 / 最小生成树 / 复杂网络 |
| 机理 | 微分方程建模 / 过程机理 / 排队论 |

**触发时机**：Phase 1 方向确认时（强制）；Phase 2 建模手选型时（复核）；Phase 2 编程异常时（可能触发重开）。

**产出**：`01_题目剖析/方向确认记录.md`（含候选思路 + tradeoff + 反驳清单 + 用户最终确定理由）。

**严格度**：**候选方向未达 ≥2 方法族、或反驳清单为空 = 不予确认方向**。

## 2. 两证

### 2.1 证据分级（防"推断写成实测"）

**目标**：在写作与引用时，让证据等级透明，避免把推断/待验证当已证实。

**分级标签**（写入文献矩阵与论文引用处）：
- `VERIFIED`：真实可查 + 数据/结论来自该来源本身。
- `INFERRED`：文献/事实真实，但结论是我们基于它的**推断**。
- `PENDING`：疑似但尚未验证，**不得作为事实引用**。

**硬规则**：
1. 论文正文的每处引用必须带上与事实相符的证据等级。
2. **`PENDING` 绝不出现在 `\cite{}`**；只能出现在"待复核清单"。
3. `INFERRED` 表述要用**限定语**（"我们推测 / 由该结果可推断 / 在该假设下…"），不得写成"文献表明 X 是事实"。

**触发时机**：Phase 2 论文手写作、Phase 3 综述检查。

**产出**：`05_论文写作/证据分级清单.md`（或随 `文献矩阵` 标注）。

**严格度**：**出现"把 `INFERRED` 写成 `VERIFIED`"、"把推断写成实测" = 列为待修项，交付前必须清零**。

---

### 2.2 可行性试点验证（严格准入）

> 也叫"最小验证实验"。**这是特权操作，只在确定的条件下才动用。**

**准入条件（全部满足才执行）**：
1. 候选方案**极度相似 / 优劣难分**，单纯从文献与理论已无法区分优劣；
2. 已在 **Phase 0 授权运行环境**（允许在用户环境中运行代码 / 调用编辑器）；
3. 存在**最小可验证实验**（小数据集运行通过 / 复现文献一个小结论），能在**很短时间**内给出可区分信号。

**执行口径**：
- 只跑最小验证，不铺开完整工程；明确"这是试点，不是最终实现"。
- 验证结论只用于**辅助用户在优劣难分时决策**，不替代正式建模/实现。
- 若条件不满足（评估耗时/成本高、或其实差异没那么接近）→ **不走此流程**，直接把 tradeoff 摆给用户最终确定。

**产出**：`01_题目剖析/可行性试点记录.md`（实验范围、结论、对决策的贡献）。

**严格度**：**默认不执行**；仅当满足全部准入条件且用户知情同意时才做。

## 3. 触发时机汇总

| 阶段 | 三查 | 两证 | 门 |
| --- | --- | --- | --- |
| Phase 1（方向确认） | 查思路（强制） | — | 未达 ≥2 族 / 无反驳清单 → 不予确认 |
| Phase 1（文献闭合） | 查真实（强制）·查贴合（强制） | — | 有未验证证据被当事实引用 / 有未映射文献 → 阻断 |
| Phase 1（优劣难分时） | — | 可行性试点验证（特权） | 准入不满足 → 不走此流程 |
| Phase 2（建模手选型） | 查思路（复核） | — | — |
| Phase 2（编程异常） | 查思路（可能重开） | — | 异常结果 → 复核 + 是否重开方向 |
| Phase 2（论文手写作） | — | 证据分级（必做） | — |
| Phase 3（综述检查） | 查真实·查贴合·查思路 | 证据分级 | 要求清零 |

## 4. 编程异常监看（Phase 2）

**触发信号**（出现任一即进入复核流程）：
- 精度指标异常（残差 / R² / 拟合误差远超预期）。
- 算法不收敛 / 迭代振荡 / 超时。
- 结果**不可解释**（符号、量级、行为与物理/逻辑直觉矛盾）。
- 数据与模型假设**不符**（分布、缺失、异常值导致失真）。

**复核流程**：
1. 判断异常**性质**：是参数/实现问题，还是**模型假设/方向问题**？
2. 若属实现/参数 → 交编程手调优（在**混合分工**下与用户一起）。
3. 若属模型/方向 → **回环建模手**，并**按查思路**判断是否需要**重开方向**（检查点而非死锁）。
4. 每一步要**留痕**到 `MMC_Journal.md` 与相应目录，并在 `state.json` 记录重开/确认状态。

**严格度**：异常结果**不允许被"草率略过"**；要么解释清楚并记录，要么触发复核/重开。

---

## 5. 与状态机的衔接

- `state.json.lit_verification`：记录每条引用的验证状态（verified/unverified/pending）。
- `state.json.pending_gates`：记录当前未通过的门（如"待用户确认某文献真实性"）。
- 每次门通过/重开后，更新 `pending_gates` 并写入 `MMC_Journal.md`（含时间戳与理由）。

---

## 6. 与用户的交互

- **每步展示 + 留窗口**：三查两证的每步结果（真实性复核清单 / 贴合度评分 / 反驳清单 / 证据分级）都要**展示给用户并留窗口**，用户可补充 / 否决（如对 `pending` 文献、对未映射文献）。
- 三查里"查真实/查贴合"多由 skill **自动执行并给出清单**，但**关键门（是否放行）需用户确认**。
- "查思路"给用户**候选 + 反驳清单**后由用户最终确定。
- 可行性试点验证**必须用户知情同意**才做。
- 所有结论以"建议"呈现，最终决策权在用户。

---

## 7. 素材搜集常见问题（为什么要有三查）

| 失败模式 | 表现 | 被哪查拦截 |
| --- | --- | --- |
| 编造引用/数据 | 引用了不存在的论文或虚构了 R²/样本量 | 查真实 |
| 低可信来源当权威 | 把博客/百科/论坛/无评审预印本当铁证 | 查真实（可信度） |
| 二手转述当一手 | 引综述转述而非原始论文 | 查真实（一手性） |
| 过时方法 | 用已过时方法而不注明有更新变体 | 查真实（时效性） |
| 文献不贴合/拼凑充数 | 记录一堆"看起来相关"但帮不上忙的文献 | 查贴合 |
| 思路固化 | 只沿着一个方向变着花样做，无 ≥2 方法族 | 查思路 |
| 把推断写成实测 | 把基于文献的推断写成"文献表明事实" | 证据分级 |
| 优劣难分硬拍 | 重要选型靠猜而非实际验证 | 可行性试点验证 |
