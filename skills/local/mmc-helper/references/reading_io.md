# 参考 · 输入读取与多模态约定

> 用途：规定处理**不同格式输入**（纯文本 / 图像 / 文档）时的读取链路与降级路径，
> 确保项目资料（赛题通知、历史论文、数据文件、图表）能被可靠读取，
> **读不出来时明确说明，绝不猜造**。
>
> **工具名说明**：下文按**能力**描述（"文本读取""视觉识别""OCR""格式转换"），
> 括号内给出常见实现名称供参考——**具体名称随所用平台而异**，按你环境里实际可用的能力对应即可。

---

## 一、按格式选读取方式

| 输入格式 | 需要的能力 | 说明 |
|---|---|---|
| `.md` / `.txt` / 代码 / `.csv` / `.json` | **文本读取** | 直接读，无需额外能力 |
| `.png` / `.jpg` / `.webp` / `.gif` | **视觉识别**（模型能读图）或 **OCR** | 若平台支持图像上传，可先落到本地再读 |
| `.pdf` | 文本层可读时按文本；图像型 PDF 需 **视觉识别 / OCR** | 先尝试文本提取，失败再走 OCR |
| `.docx` / `.doc` | **格式转换**（转 Markdown 或纯文本） | 转换后再按文本读取 |
| Excel / 表格类附件 | **表格读取** | 直接读表；必要时转 CSV |

---

## 二、读取之前先问一句（关键）

读取任何需要**视觉或 OCR**的文件之前，先向用户说明并确认：

> "接下来要读的是 [图像 / 图像型 PDF]，需要模型能读图（多模态）或具备 OCR 能力。
> 你当前**是否已开启多模态**？"

- **已开启** → 正常读取；
- **未开启 / 不确定** → 走降级路径（见下）。

**为什么要问**：读不出来却硬读，会产出编造内容——这是本项目最不可接受的错误之一。

---

## 三、降级路径（能力不足时）

| 情形 | 降级做法 |
|---|---|
| 无视觉能力 | 用 **OCR** 提取文字；OCR 结果仅作**线索**，关键数值须复核 |
| 无 OCR 也无视觉 | 请用户**提供文本版**（粘贴关键段落、或导出为文本/CSV） |
| 文档格式读不了 | 用**格式转换**工具转 Markdown；或请用户另存为 `.txt` / `.csv` |
| 图表读不全 | 请用户说明图的关键信息（坐标范围、单位、趋势），并**在留痕中标注"由用户口述"** |

**最后手段**：明确列出"**需要你提供什么**"（哪一页、哪一段、哪个数值），
**宁可停下来问，也不要补全**。

---

## 四、不编造原则

- 读不出的内容（OCR 模糊、被截断、付费墙）→ 标注"**读不全 / 待用户提供**"，
  并接入 `protocols/quality_control_protocol.md` 的**证据分级**：未核实的内容不得当作事实使用；
- 若整份素材读不了 → 向用户说明，并给出**取舍建议**（这份资料是否必须有、能否换一份）；
- **绝不用"看起来合理"的内容填补读不出的部分**。

---

## 五、在流程中的落点

| 阶段 | 常见输入 | 注意 |
|---|---|---|
| **Phase 0** | 赛题通知/注意事项（PDF/DOCX）、用户历史论文（PDF） | 先确认多模态或走降级路径 |
| **Phase 1** | 数据文件（CSV/Excel，纯文本，直接读）、示意图与图表（图像，需视觉） | 数据文件以"能解析出数值"为准 |
| **Phase 2** | 运行结果图、用户提供的代码或截图 | 图用于判读时，关键数值仍以程序输出为准 |
| **全程** | 凡涉及图像/PDF，一律先确认能力，再选路径 | 不确定时先问，不要试错式硬读 |
