# 参考 · 工具与环境适配指南

> **本 skill 不绑定任何平台、语言或软件。**
> 本文说明：在不同环境下如何保持同一套流程与交付标准；缺能力时如何降级。

---

## 一、Phase 0 必须问清的技术栈

| 项目 | 要问什么 | 为什么重要 |
|---|---|---|
| **编程语言与求解器** | 用 Python / MATLAB / R / Julia / LINGO / Gurobi / SPSS / Excel？ | 决定编程手写什么、运行说明怎么写、依赖怎么装 |
| **代码编辑器 / IDE** | VS Code / PyCharm / MATLAB 自带 / 纯文本？ | 决定能否"打开文件给用户看"、单章预览怎么做 |
| **排版工具** | LaTeX / Word / Markdown？ | 决定写作规范与编译/排版检查的方式 |
| **版本控制** | 用 git 吗？ | 决定改动能否回滚、留痕怎么组织 |
| **运行权限** | 是否允许在用户环境中运行代码与命令？ | 未获授权不得执行 |
| **平台能力** | 有无终端 / 子智能体 / 多模态读取 / 联网检索？ | 决定哪些协议走主路径、哪些走降级路径 |

**结论写入 `state.json`**，后续所有角色据此工作。

---

## 二、按能力的降级路径

| 能力 | 有 | 没有时的降级 |
|---|---|---|
| **终端执行** | 直接跑代码、读输出 | 由用户在其环境中运行并把输出贴回；智能体只**写代码 + 运行说明 + 判读结果** |
| **子智能体** | 审核手用干净上下文（隔离最好） | 同会话切换 persona，**只允许读 `audit_package/`**，并在报告中声明"独立性较弱" |
| **多模态读取**（图/PDF） | 直接读图与扫描件 | 走 OCR / 格式转换；仍不行则**列出"需要用户提供什么文本"**，不编造 |
| **联网检索** | 现场更新方法库与文献 | 用用户提供的资料 + 内置方法矩阵；**明确标注来源缺失** |
| **版本控制** | git 管理改动、可回滚 | 改动前手工备份；关键节点另存副本 |
| **编辑器调用** | 打开文件给用户看 | 让用户自行打开指定路径，或用预览文件代替 |

**原则**：能力缺失**只改变执行方式，不降低交付标准**——闸门、留痕、审核照旧。

## 三、按技术栈的注意事项

### 3.1 编程语言与求解器

- **不预设语言**：编程手按用户既有环境写代码；换语言不改变职责边界与交接闸门；
- **运行说明必须写清**：语言与版本、求解器与版本、依赖安装、运行命令、预计耗时；
- **可复现要求通用**：随机种子固定、数据来源明确、**一键可重跑**（或说明为何不能）；
- **调试与验收方式因语言而异**：数值双验、量级核对、残差检查等要求与语言无关。

### 3.2 排版工具

| 工具 | 写作与检查要点 |
|---|---|
| **LaTeX** | 见 `templates/latex_workflow.md` 与 `references/latex_bib_guidelines.md`（工程组织、单章预览、引用核对、编译指标） |
| **Word** | 样式统一（标题层级 / 题注 / 表格体例）；**逐图逐表核对编号与引用**；用"交叉引用"而非手写编号；导出 PDF 后做渲染抽查 |
| **Markdown → PDF** | 固定模板与转换链路；转换后同样要抽查渲染结果 |

**通用要求（与工具无关）**：
- **章节层级按官方模板折算**，不擅自把每个子问题做成顶层章；
- **图表体例统一**：字号 / 框线 / 对齐 / 汇总行一次定死；
- **题注与内容必须相符**（常见病：题注写"四种"，图里只有两种）；
- **交付前做渲染抽查**：确认编号、引用、公式、表格没有错乱。

### 3.3 编辑器与预览

无论用什么编辑器，**"改一处、立刻看到结果"**这一条都要保住：

- 分文件组织（一章一文件）→ 可单独预览、可并行编辑；
- 若工具支持"只编译/渲染当前章"，就用它；不支持时，把该章抽成独立的临时文件单独渲染；
- 预览与全文的**引用编号要一致**（做法见 LaTeX 工作流；其它工具同理）。

### 3.4 版本控制

- 有 git：按功能提交、关键节点打标签；改动前后对比方便；
- 无 git：改动前**先备份**；把"谁在什么时候改了什么"写进留痕。

## 四、跨平台的角色分工

角色分工与平台无关，但**承载方式**可不同：

| 角色 | 平台支持子智能体 | 平台不支持 |
|---|---|---|
| 建模手 / 编程手 / 论文手 | 可分别用子智能体 | 同一会话按阶段切换 persona |
| **审核手** | **优先**用干净上下文的子智能体 | 同会话 + 只读白名单目录 + 声明独立性较弱 |

**无论哪种方式**，「完成 → 展示 → 留窗口 → 用户意见 → 执行」都不变。

Phase 0 结束时确认：

- [ ] 编辑器 / 排版工具已问清

- [ ] 平台能力已盘点（终端 / 子智能体 / 多模态 / 联网），**缺哪些已记下并选定降级路径**
- [ ] 是否使用版本控制已确认（并据此决定备份策略）
