# 方法谱系 + 问题特征→推荐矩阵

> 用途：给 Phase 2 **建模手**提供"问题特征 → 候选模型"的**直接可用候选池**，避免临时消化检索。
> 设计：**内置库 + 现场检索**双保险（跟上方法迭代），常规候选 + **进阶/极端后备**（防难题），并给每个候选**一句话简介 + 代码示例**方便用户判断。
> 配套：`quality_control_protocol.md`（查思路：候选须 ≥2 方法族）、`templates/model_spec_template.md`、`lit_search_protocol.md`。

---

## 0. 用法（建模手匹配流程）

1. **抽特征**：对每个子问题按 §2 抽取特征。
2. **查内置候选池**：按"任务类型 + 数据形态"查 §3 矩阵，得 2-3 个**常规**候选。
3. **现场更新方法库（双保险）**：针对该子问题做一次**定向检索**（见 §5），确认是否有**更新/更贴合**的方法，并入候选。
4. **调进阶后备**：若常规方案不足以应对高难度，查 §4 **进阶/极端后备**，看是否有更精细/更狠的方案。
5. **补 tradeoff**：给每个候选列适用条件 / 复杂度 / 风险 / 推荐度。
6. **保 ≥2 方法族**：候选若落在同一方法族，需跨族补一个（接三查两证·查思路）。
7. **简要介绍方案**：给每个候选**一句话简介**（是什么、为什么贴这道题）+ 参考代码示例（§7），帮用户做判断。
8. **用户最终确定**：把候选 + tradeoff + 简介 + 代码示例给用户，由用户选定。
9. **落成模型规格书**：写入 `templates/model_spec_template.md`（含达标判据、预期输出、反驳清单）。

## 1. 方法谱系（内置基线）

| 族 | 常见方法 |
| --- | --- |
| **评价·决策** | AHP、TOPSIS、DEA、熵权法、模糊综合、主成分（降维打分）、灰色关联、秩和比、BWM |
| **优化·规划** | 线性/整数/0-1/目标/非线性规划、动态规划、灵敏度分析、遗传、模拟退火、粒子群、蚁群、NSGA-II（多目标）、梯度法 |
| **预测·时间序列** | 线性/多元/逐步回归、ARIMA/ARMA、指数平滑/Holt-Winters、GM(1,1)、马尔可夫、LSTM/RNN、BP 网络、SVR、随机森林、XGBoost、插值/拟合 |
| **统计·分类** | K-means、层次聚类、DBSCAN、GMM、判别分析、SVM、决策树、随机森林、朴素贝叶斯、逻辑回归、卡方/方差/假设检验、相关性分析 |
| **降维·特征工程** | PCA、因子分析、LDA、t-SNE、对应分析、特征筛选 |
| **图论·网络** | 最短路径（Dijkstra/Floyd）、最小生成树、最大流/最小割、指派（匈牙利）、TSP（遗传/蚁群）、复杂网络（中心性/社区发现/度分布） |
| **机理·微分方程** | 常/偏微分方程、传染病（SIR/SEIR）、捕食者-猎物、排队论（M/M/1 等）、差分方程、元胞自动机 |
| **随机·模拟** | 蒙特卡洛模拟、随机过程、确定性/随机性建模 |
| **数据·可视化** | 数据清洗/插补、异常值处理、可视化、统计检验 |

> 这是**内置基线**，会随 §5 现场检索**动态补充**前沿方法，不必写死。

## 2. 问题特征抽取

- **任务类型**：评价 / 优化 / 预测 / 分类 / 排序 / 分配 / 路径 / 机理 / 模拟。
- **数据形态**：表格（截面/时序/面板）？图像？文本？网络？机理已知否？
- **规模与约束**：变量数、样本量、约束条件、是否多目标。
- **要求**：需显式解释性？精度 vs 可解性优先？需可复现/可校验？

## 3. 特征 → 推荐矩阵（常规候选池）

> "推荐度"= 综合赛题契合度、实现难度、可解释性、可复现性后的**默认倾向**，非强制排序。

| 子问题形态 | 候选 1（首推） | 候选 2 | 候选 3（备选） | 适用条件 | 风险/提醒 |
| --- | --- | --- | --- | --- | --- |
| 多指标综合评价 | TOPSIS | 熵权法+AHP 组合 | 灰色关联/模糊综合 | 决策矩阵完备、需排序 | 权重主观；说明权重来源 |
| 客观赋权/无偏好评价 | 熵权法 | 变异系数法 | CRITIC | 数据充足 | 极端值敏感，需预处理 |
| 效率/投入产出评价 | DEA（CCR/BCC） | 超效率 DEA | 熵权-TOPSIS 对比 | 多投入多产出 | 需明确投入/产出指标 |
| 单目标工程优化 | 线性/非线性规划 | 整数/0-1 规划 | 遗传算法 | 模型可解析、规模不大 | 局部最优；大模型注意时长 |
| 多目标优化 | NSGA-II | 加权和转单目标 | 分层序列法 | 存在权衡 | Pareto 前沿解释；权重说明 |
| 组合/路径/指派 | 匈牙利（指派） | 遗传/蚁群（TSP） | 动态规划 | 结构清晰 | NP 难；给出近似解解释 |
| 中短期时间序列预测 | ARIMA | Holt-Winters 指数平滑 | 回归 | 平稳/趋势+季节性 | 平稳性检验；外推不确定度 |
| 数据驱动预测（样本充足） | 随机森林 / XGBoost | SVR | LSTM（时序） | 特征多/非线性 | 可解释性差，需特征重要度 |
| 小样本/少数据预测 | GM(1,1) | 简单回归 | 马尔可夫 | 数据少、呈指数趋势 | 适用性检查；不能硬套 |
| 机理演化/过程建模 | 微分方程（RK 解） | 差分方程 | 元胞自动机 | 机理已知 | 参数识别；初边界条件 |
| 传染病/扩散类 | SIR/SEIR | 分段或加接种模型 | 模拟 | 需刻画传播 | 参数拟合；假设说明 |
| 排队/服务系统 | M/M/1 等排队论 | 模拟 | 微分方程 | 到达/服务率可估 | 稳态假设；服务率估计 |
| 聚类/分群 | K-means | 层次聚类 | DBSCAN | 需分群 | K 选择；DBSCAN 参数 |
| 分类判别 | 判别分析 | SVM | 决策树/随机森林 | 类别标注 | 类别不平衡 |
| 降维/多变量结构 | PCA | 因子分析 | t-SNE（可视化） | 变量多、冗余 | 解释方差；载荷解释 |
| 相关性/显著性检验 | 相关性分析+假设检验 | 方差分析 | 回归显著性 | 需量化关系 | 相关≠因果 |
| 数据缺失/异常 | 插补（均值/插值/模型） | 异常值处理 | 数据清洗 | 数据不全 | 插补假设需说明 |
| 敏感/稳健性分析 | 单参数扫描 | 蒙特卡洛 | 扰动分析 | 需验证稳健性 | 收尾必备，别漏 |

## 4. 进阶 / 极端后备方案（防难题 · 特殊细致库）

> 当常规候选**不足以应对题目高难度、或题目明显超纲/需更精细方法**时，从本表取**更极端/更细致的后备**。触发条件写在"何时用"列。

| 子问题形态 | 进阶/极端后备 | 何时用 / 说明 |
| --- | --- | --- |
| 评价（复杂/群决策） | 区间直觉模糊、云模型、群决策集结、变权 AHP、组合赋权（主客观+博弈论） | 评价维度多/意见分歧大/指标取值带区间时 |
| 优化（大规模/强非线性） | 混合算法（遗传+局部搜索）、精确求解器（Gurobi/CPLEX）、分解法（LNS/列生成） | 规模大、可行域复杂、普通算法跑不动 |
| 预测（复杂时序/多变量） | 混合模型（EMD/VMD+ARIMA+LSTM）、Transformer/深度学习、组合预测（方差倒数/最优加权）、贝叶斯方法 | 时序强非线性/多变量/需更高精度时 |
| 聚类（形状/密度复杂） | GMM、谱聚类、密度聚类（DBSCAN/OPTICS）、自适应 K | 数据非凸、密度不均时 |
| 图论（大规模） | 启发式 + 精确校验（分支定界）、网络流+最小割、社区发现算法 | 规模大、需近似但有界 |
| 机理（参数辨识难） | 数据同化、卡尔曼滤波、灵敏度+不确定度量化 | 参数难定、需刻画不确定性时 |
| 数据缺失（复杂） | 多重插补、贝叶斯插补、生成式补全、模型插补 | 缺失模式复杂、需可靠推补时 |
| 敏感性（全局） | Sobol 全局敏感性、多项式混沌、参数扰动+区间分析 | 需全面刻画参数影响时 |
| 分类（类别不平衡/文本图像） | SMOTE/代价敏感/集成、CNN/Transformer（图像文本） | 类别失衡、或输入为图像/文本时 |
| 优化求解可靠性 | 多起点 + 全局收敛判据、变异系数检验解稳定性 | 需要证明解不是偶然局部最优时 |

> 选用进阶/极端后备**务必说明"为什么常规方案不够、为什么它更合适"**，避免为了过度表现而强行采用。

## 5. 现场更新方法库（内置 + 现场并行 · 双保险）

> 目的：**内置库可能跟不上方法迭代**，尤其近年题目变难、迭代快。进入 Phase 2 建模步骤时，做一次**定向现场检索来补充/刷新方法库**。

**做法**：
1. **定向检索**：用"子问题关键词 + 候选方法"做一次检索（`web_search`），确认是否有**更新 / 更贴合**的方法（新变体、组合、开源实现）。默认自包含完成；若用户另有更强的检索渠道，可在其同意下加深检索。
2. **刷新候选**：把检索到的新方法**并入 §3 候选池**，标"现场发现"。
3. **保 ≥2 方法族 + tradeoff**：新方法同样走"查思路 + tradeoff"，不能为了新而新。
4. **成本控制**：现场检索**只做一次、只在要定方案时做**，不做无谓漫搜；关键默认入过时间盒。
5. **留痕**：新方法及来源写入 `01_题目剖析/方向确认记录.md` 与文献矩阵，标注贴合度。

**与 §4 的关系**：§4 是**预先备好的**进阶库；§5 是**当场补的**新方法。二者叠加，保证"常规方案 + 进阶后备 + 最新方法"三层都有。

## 6. 推荐度判定依据

- **赛题契合度**：是否直接对应子问题题型（最高权重）。
- **可解释性**：评审偏好清晰、能讲清"为什么用这个"。
- **实现难度 / 时间**：在竞赛时间盒内能否运行通过、调参可控。
- **可复现性**：结果稳定、可校验、便于论文呈现。
- **用户画像**：`user_profile.md` 显示用户取矩阵偏简单/偏深时，可向"耐解释+可控"或"更有创新"微调，但**以稳为主**。

## 7. 方案简介 + 代码示例（便于用户判断）

> 给用户候选时，**每个候选配一句话简介 + 实现要点**，让用户一眼看懂"这是什么、为什么合适、大概怎么落地"，再做判断（对应分工模式"混合"的"我搭骨架你验证"）。

**一句话简介模板**：`<方法名>：<它是干什么的>，<为什么贴这道题>，<主要成本/风险>。`

**实现要点**（**语言与工具无关**）：每个候选给三样东西——**输入输出是什么、关键步骤有哪几步、
  实现上最容易踩的坑**。用用户选定的语言与求解器写骨架；**不预设 Python / MATLAB / R 或任何库**。

| 方法族 | 实现要点（与语言无关） |
|---|---|
| 评价类（如 TOPSIS / 熵权法） | 指标标准化 → 权重（熵权 / AHP / 变异系数）→ 与理想解的距离 → 排序；注意**指标方向**（正向化）与量纲 |
| 优化类 | 明确决策变量、目标、约束的形式（线性 / 整数 / 非线性）→ 选求解器 → 检查**是否返回最优状态** → 报告对偶或边际信息 |
| 预测类 | 划分训练/验证集 → 选模型族 → **只用历史数据定参** → 用统一误差指标比较 → 检查残差结构 |
| 聚类 / 分类 | 特征标准化 → 选簇数或分类器 → **给出稳定性或交叉验证结果** → 解释各类的含义 |
| 机理 / 微分方程 | 写清状态方程与边界/初值 → 选积分器 → **检查守恒与量级** → 做步长或参数敏感性 |

> 候选阶段只给**核心骨架与实现要点**；完整实现与调优交正式建模阶段。
> 语言与求解器的选择以用户环境为准（见 `references/tool_and_env_guide.md`）。

## 8. 补充说明
- 特定题型（图像/文本/深度学习）的**常规**候选直接并入 §3。
- 各方法族的**实现要点**见 §7；具体代码由编程手按用户环境生成，**不预设语言**。
- 与 `competition_profiles.md` 绑定：不同竞赛对"模型创新"权重不同，可微调推荐序。

## 9. 使用建议

1. **先定问题类型，再选方法族**：优化 / 预测 / 评价 / 分类聚类 / 机理仿真，各自的方法族不同；
2. **候选必须 ≥2 个方法族**：单一思路容易固化；给出 tradeoff 与反驳清单后由用户拍板；
3. **匹配度优先于先进性**：用得上、讲得清、算得动，比"方法新"更重要；
4. **先验证可行性再铺开**：数据量、精度要求、时间盒是否支撑所选方法；
5. **方法要能落到数据上**：先看数据有什么，再决定能做什么；
6. **记下选择理由**：为什么选它、为什么不选备选——这是答辩与论文"模型分析"章的素材。
