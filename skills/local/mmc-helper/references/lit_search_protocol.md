# 高精度文献检索协议

> 用途：避免"泛泛搜索"，针对子问题做高精度、最相关、最直接的检索。

## 1. 检索前：关键词拆解
- 题目关键词 → 模型关键词 → 方法关键词，逐层拆解后再检索。

## 2. 分层渠道
| 层级 | 渠道 |
| --- | --- |
| 中文文献 | 知网 / 万方 / 维普 / 数学建模专刊 |
| 英文文献 | Google Scholar / arXiv / Semantic Scholar / OpenAlex / Crossref API |
| 代码实现 | GitHub / Papers-with-Code |
| 论坛 | 数学中国等数学建模社区 |

## 3. 付费墙处理
- 无法直接获取时：给用户"从哪个方向去搜、找什么、如何取舍"的建议 → 用户代为寻找并反馈 → skill 再筛选整合。

## 4. 产出
- annotated bibliography + `.bib` 文件 + 文献矩阵表（文献 ↔ 子问题 ↔ 提供模型/方法 + 贴合度评分）。

## 检索的四个步骤

1. **拆需求**：把子问题拆成"要解决什么 + 需要什么依据"两类问题；
2. **定关键词**：中文与英文各准备一组，覆盖"问题域 + 方法域"；
3. **多源交叉**：学术检索源 + 出版方页面 + 预印本库；**同一结论尽量有两个来源**；
4. **逐条核实**：题名、作者、年份、卷期页、DOI 是否齐全且自洽；
   **核实不到的标为待核实，不得当作事实引用**。

## 判定与分级

- **已核实**：有可解析的 DOI 或出版方页面佐证；
- **待核实**：存在但要素不全 → 只作线索，不写入引用库；
- **不可采信**：来源不明、AI 生成文档、无许可的代码仓库等。

## 与写作的衔接

- 引用要**支撑具体论点**，不为凑数而引；
- 引用位置与正文论点一一对应；
- 交付前做一次"正文引用 ↔ 引用库"的双向核对。
