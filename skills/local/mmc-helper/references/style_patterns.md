# 参考 · 写作范式库

> 用途：论文手动笔前后的**文风依据**。本库只教"**该怎么写**"，不教"不许写什么"。
> 维护方式：每当用户对文本提出修改，就把"**原稿 → 问题 → 改法**"三列记入本库对应章节。
> 本库应随项目持续增长；新项目开工时先读本库，再读项目内的成稿样本。

---

## 一、六条底层规律

从大量用户改写中归纳出的稳定规律。**规律比禁用词表更可迁移**——因为用户给的从来不是
"不许写某个词"，而是"这件事该怎么说"。

### 规律 1｜把抽象概念还原成事实
用户不接受"概念名词"，要求**说出这件事本身**。

| 概念化表达 | 应还原为 |
|---|---|
| 共享同一套物理内核 | 都采用相同的约束条件 |
| 存在跨时段耦合 | 各时段会通过状态变量相互影响 |
| 写成结构性约束 | 已经执行的时段不能重新修改 |
| 遵循信息可用性规则 | 每个决策时刻只使用当时已经获得的信息 |
| 把依据与保护分开处理 | 先预测，再为预测误差预留余量 |

**判据**：如果一个短语能被替换成一句"**谁在什么时候做什么**"的直白陈述，就必须替换。

### 规律 2｜删除自我辩护与过度证明
| 原稿 | 判断 |
|---|---|
| 若按另一种读法，还须额外假定…… | 自我辩护过长 |
| 该处理直接来自数据的粒度，不引入额外误差 | 没有必要证明得这么满 |
| 其作用有且只有两个 | 语气过强、像答辩 |
| 与给定数据在能量上严格一致 | 强调过度 |

**判据**：假设、设定只需**声明 + 一句简短理由**（2–3 句），不在前文提前打完所有官司。

### 规律 3｜不承诺后文不存在的内容
| 原稿 | 判断 |
|---|---|
| 并在后文讨论该假设的影响量级 | **后文并未对应展开 → 删除** |

**判据**：写下的每一个"后文将……"都必须在后文**真的存在**。

### 规律 4｜去代码味与开发味
| 开发/审计语言 | 论文语言 |
|---|---|
| 数据链条连续运行后再按日期切片 | 从某日起连续运行，再截取报告期 |
| 机器零 / 逐位一致 / 逐位复现 | 最大数值偏差为 0 / 完全相同 |
| 口径（效率口径、费用口径、主口径…） | 设定 / 定义 / 基准方案 |
| 反证 | 未来扰动检验 / 因果性检验 |
| 对拍 | 逐一核对 |

**判据**：凡是在**编程或核对过程**中自然形成的词，一律不得进入论文。

### 规律 5｜AI 式总结句要拆成并列事实
| 原稿 | 判断 | 改法 |
|---|---|---|
| 三项主要特征直接影响后文的建模选择 | AI 式总结句 | **直接分别说明三个特征及其用途** |
| 随后给出三层结论 / 两处设计需要说明 | 元叙述 | 删除，直接写内容 |
| 这一结果充分说明……／实现了……的有效统一 | 空泛评价 | 换成带数字的具体结论 |

**判据**：**不做元叙述**——不告诉读者"我要说几件事"，直接把事说完。

### 规律 6｜不越位——章节各司其职
| 原稿 | 判断 |
|---|---|
| 在数据章提前给出完整的技术方案 | 越位；数据章只给**现象与事实** |
| 在分析章提前证明模型正确 | 越位；分析章只给**难点与思路** |

**判据**：每章只做自己那一层的事。

## 二、句式与用词范式

### 2.1 连接词分档使用
| 场合 | 用词 |
|---|---|
| 章首列举"与前一问/前一阶段的差异" | **一是…二是…最后则是…**／**首先是…其次是…再者则是…最后是…** |
| 列举补充假设 | **其一是…其二是…其三是…** |
| 因果 | **故 / 遂 / 则 / 据此 / 因此 / 从而** |
| 让步反证 | **如若…则…**／**若…则应该不会出现…** |
| 补充并列 | **而 / 而非 / 同时** |
| 领出结论 | **由表 X 可知／由图可知／由上文的图表可以得知／可见** |

### 2.2 "而非"与"而不是"要区别对待
- **保留**："**而非**当日的修正""**而不**截断到当日结束"——短且必要的对比；
- **删除**："…自然得到，**而不是人为设定**"——长且是自证。

**判据**：对比从句**短且用于区分两种做法**保留；**长且用于说明"我不是那种做法"**删除。

### 2.3 软化断言动词
| 硬 | 软 |
|---|---|
| 因此采用……求解 | 因此**考虑**采用……求解 |
| 保证某变量只能表示…… | **以确认**某变量只表示…… |

### 2.4 结果句要有动作词
"代入数据后，……为 X" → "代入数据后，**最终计算得到**……为 X"。
体现**这是求解结果而非设定**。

### 2.5 删冗余限定词
"**题目要求的**指定时段数据" → "**要求的**指定时段数据"（上下文已知的信息不必反复冠名）。

### 2.6 并列对象合并成一段
三个并列的特征／对象，写成**一段三句**，每句"特征 + 数字 + 因此后文怎么做"，
不拆成三个小标题或三段。

### 2.7 数字与符号
- 所有数字与时刻进数学模式，保证字体与间距一致；
- 千分位逗号只用于**正文叙述与表格**，公式内不加。

## 三、人称与视角

### 3.1 署名主体用"我们"
竞赛论文里 **"我们"是被鼓励的**（体现"本队做了这件事"），"本文"反而生硬。
**不得以"更学术"为由把"我们"改成"本文"。**

| 类型 | 示例 |
|---|---|
| 承接任务 | 按上述变化，**我们**需要依次解决几个问题：… |
| 声明选择 | **我们考虑**采用……；**我们考虑借用**这一思路 |
| 声明设定 | 另外**我们考虑**设立三个补充假设 |
| 规定规则 | 为保证……，**我们规定**…… |
| 陈述实现 | **我们使用**……库进行构造并求解 |
| 领读结果 | **由上文的图表我们可以得知**……／**我们计算得到**…… |
| 表达立场 | **我们认为**本问并不需要新建模型，而仅需要…… |
| 承接题面设问 | **我们被要求**分析…… |

### 3.2 人称随章节功能切换
| 章节类型 | 人称 |
|---|---|
| 问题章（写"本队做了什么"） | **我们** |
| 检验章（写"本队做了哪些检验"） | **我们** |
| 评价章（对模型的客观判断） | **不用"我们"**，改由"模型／本文的模型"作主语 |

**⚠️ 改人称时必须复读整句**：删掉"我们"后常出现**缺主语病句**。

### 3.3 本队判断要标注出处
当正文给出的是**本队自己的判断**（而非标准做法）时，明确标注：
> 「**这也是我们对该设问的进一步考虑**：……」

以免与文献结论混淆。

## 四、图与表的写法

### 4.1 图的说明顺序
1. **先给读图指引**："图为……平面上的分布图，横轴为……、纵轴为……、颜色深浅表示……"；
2. **再给结论**："由图可知，……高度集中……"。

对**信息量大的图**（热力图、谱图等）必须先指引后结论；对**折线图/直方图**可直接给结论。

### 4.2 表格的单一来源
同一篇论文里，表格的字号、框线形式、对齐方式、汇总行写法**必须统一**。
建议在写作契约里一次定死，不在各章分别决定。

---

## 五、方法论述的写法

**先给文献版图，再说本题条件，最后说我们选了什么**：
> 「……在该领域已有多种路线，既有 A 类方法，也有 B 类方法[1-4]；
> **考虑到本题只提供 X 与 Y，故采用**……」

这优于"我们的模型是……，这与文献[X]的思路相近"——**文献在前、选择在后、选择有理由**。

---

## 六、维护本库的方法

1. 用户每次提出文本修改，记入"原稿 → 问题 → 改法"三列表；
2. 每积累若干条，回头**归纳新的底层规律**（六条规律就是这样得来的）；
3. **新项目开工时，先读本库 + 再读该项目的成稿样本**；
4. 若用户的成稿与用户口头规则冲突，**以成稿为准**（成稿才是他真正认可的形态）。

# 附 · 一篇好论文长什么样

> 许多参赛者并不知道"什么样的论文算好"——这不是他们的错：评判标准很少被写下来。
> 本节把标准写成可操作的样子，供写作前自问、写作后自检。

## 一、评委怎么读一篇论文（决定了一切写法）

评委在有限时间里通常这样读：**摘要 → 图表 → 结论 → 才可能读正文**。
由此推出三条硬要求：

1. **摘要必须独立成立**：读摘要就能知道"做了什么、怎么做的、得到什么"；
2. **图表必须自明**：只看图表与题注也能看懂结论；
3. **结论必须在显眼处**：每张表/图之后的第一句就给出结论，而不是铺垫完再说。

## 二、六条可自检的质量标准

| 标准 | 自检问题 | 不合格的表现 |
|---|---|---|
| **1 有据** | 每个数字都能追溯到程序或结果文件吗？ | 出现"约为""大致"这类估数；结论超出数据能支撑的范围 |
| **2 可复现** | 别人拿到你的程序与数据，能算出同样的结果吗？ | 结果与程序对不上；关键参数来源不明 |
| **3 可读** | 不懂本领域的人能读懂主线吗？ | 术语堆砌；概念包装；不做解释就抛公式 |
| **4 自洽** | 前后设定一致吗？符号统一吗？ | 同一件事前后两种说法；符号重复定义 |
| **5 诚实** | 局限写清楚了吗？负面结果保留了吗？ | 只讲优点；把"未做"写成"做了"；回避反例 |
| **6 完整** | 题面要求的每一项都回应了吗？ | 漏答小题；交付物与题目要求不一致 |

## 三、优秀论文的共同特征（可模仿的形态）

1. **一篇一个主线**：所有章节都在回答同一个问题，后一节建立在前一节之上；
2. **结构可预期**：重述 → 分析 → 假设 → 符号 → 逐问建模与求解 → 检验 → 评价 → 附录，读者能预判；
3. **结果先于解释**：先给结论句，再给数字，最后给原因；
4. **对照说话**：凡有主张必有对照（与基线、与另一方法、与另一设定），
   并明确"只差哪一维"；
5. **难点被正面处理**：不回避题目的坑，而是把坑写成"我们怎么处理的"；
6. **篇幅花在该花的地方**：模型建立与结果分析详写，软件实现与模板性内容压缩。

## 四、常见扣分点（写完之后对照一遍）

- 摘要写成背景介绍，没有方法与结果；
- 图表没有解读，或解读只是复述数字；
- 结论超出数据（用"显著""充分证明"这类强断言）；
- 只写优点，不足写成"未来可以引入更大的模型"这类空话；
- 交叉引用失配、编号错乱、编译告警未清；
- 附录塞满源码导致页码超限；
- 引用数量偏少或来源不规范；
- 同一篇里格式不统一（字号、框线、对齐、人称）。

## 五、写作前的三个自问

1. **如果评委只读摘要，他会知道我们做了什么吗？**
2. **如果评委只读图表，他能看懂结论吗？**
3. **如果评委质疑我们的某个假设，我们准备好在哪一节回应他？**
