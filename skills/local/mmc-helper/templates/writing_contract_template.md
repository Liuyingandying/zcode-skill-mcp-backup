# 写作契约（增量台账）

> **这是什么**：本项目**当前生效**的全部写作要求的唯一来源。
> **怎么用**：不是"开工前一次问全"，而是**增量维护**——用户每提一条要求，立即记入本表并**全篇执行**。
> **配套**：可脚本化的条目应转成检查项，编译后自动跑（见 `templates/latex_workflow.md`）。

## 二、须固定下来的六类内容（开工前先与用户确认）

### 2.1 人称与视角
- [ ] 署名主体用"我们"还是"本文"？（建议：**正文用"我们"**）
- [ ] 各章人称是否随功能切换？（建议：**评价章不用"我们"**）
- [ ] 是否有"不得以更学术为由改人称"的约定？（**建议写入，且为硬约束**）

### 2.2 禁用与必用
- [ ] 禁用词表（开发/审计语言、AI 套话、口语比喻、引号简略词……）
- [ ] 必用范式（抽象概念如何还原成事实；结论如何写）
- [ ] 章节职责边界（每章只做自己那一层的事）

### 2.3 公式与符号
- [ ] 公式解释的形式（如"主体段 → 公式 → 式中段"）
- [ ] 变量与取值范围的位置（公式前 / 后）
- [ ] 符号集中说明的范围（全部 / 仅高频，局部符号就近定义）
- [ ] 编号与引用规范

### 2.4 表格（**单一来源**）
- [ ] 字号（全篇统一）
- [ ] 框线形式（题面规定格式 vs 自选格式，分别定死）
- [ ] 对齐方式（全居中 / 全靠左，不得混排）
- [ ] 汇总行的写法
- [ ] 表头与表体的间距

### 2.5 图
- [ ] 尺寸（核心图占正文宽度比例）
- [ ] 图内是否写标题（**建议不写**，交给图注）
- [ ] 说明顺序（读图指引 → 结论）
- [ ] 字体（**必须选本机实测存在的**）

### 2.6 引用与数字
- [ ] 引用编号顺序（按正文出现顺序）
- [ ] 著录格式
- [ ] 数字精度与单位（正文/表格/公式分别规定）
- [ ] 同一数字是否允许在章内重复报告

---

## 三、维护规则

1. **用户每提一条，立即入表**（不要攒着）；
2. 入表后**立即全篇扫描**，把违反点写入"全篇扫描结果"列；
3. 扫描发现"语义特殊、不确定是否违反"的，单列出来**请用户判断**；
4. 已作废的条目**不删除**，标记为作废并注明替代者（便于回溯）。
