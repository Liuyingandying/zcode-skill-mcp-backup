# 示例 · 端到端人机协同演示（用户 / 智能体对话）

> 演示沿用"共享电单车调度"题，工作模式选 **B 全权代理（透明知会）**。整体体现：**每步"智能体完成 → 展示 → 留窗口 → 用户意见 → 智能体执行"**，阶段间设"用户同意才进下一阶段"的闸门，关键决策点强确认，**用户全程知情、可随时插入**。数据与结论为虚构。

> **示例中的技术栈（语言、编辑器、库）仅为举例**——实际以你在 Phase 0 确认的环境为准；
> 换成 MATLAB / R / LINGO / SPSS 或别的编辑器，流程与留痕要求完全相同。
> 通用适配见 `references/tool_and_env_guide.md`。

---

## 一、开场 · 预准备（Phase 0 开头）

**智能体:** 你好！我来协助这次数学建模。先确认两件关键的事。① **工作模式**，你要哪种？
- **A 仅协助**：我每步做完都会停下等你意见，你全程主持。
- **B 全权代理**：我更自主推进，但**每步都会告诉你我在做什么、留窗口给你**，关键决策点（选模型/定方向/是否收尾）必找你确认。

**用户:** 选 B，全权代理。但每步都要让我看到。

**智能体:** 好，按 **B 全权代理（透明知会）**。② 请给我这几样（没有的可以说"没有"）：赛题 / 赛题通知 / 注意事项（PDF 或文字）；团队分工；编程环境（用不用 VSCode、Python 版本）；过往参赛论文（可选）；**针对这道题的目标优秀论文/获奖作品**（可选，我用它对齐写作结构；没有就用内置获奖论文学习库）。

**用户:** 题和通知给你（PDF）。我、李、王三人：我建模、李编程、王写作。用 VSCode、Python3.11。去年论文给你。目标优论没有。

**智能体:** （读 PDF → 提取）解析出：**国赛、3 天、提交 PDF、今年要附 AI 使用说明、禁用某数据源**。**展示**【竞赛 Profile】，确认或纠正。

**用户:** 对。

## 二、Phase 0 · 立项（每步"展示→窗口"）

**智能体:** 图像性 PDF 需要多模态。你**当前已开启多模态**吗？没开启我就走 OCR / 请你转文本。

**用户:** 开了，直接读。

**智能体:** 好。团队分工与里程碑我排好了，**展示**【第 1 天上午剖析+方向、下午~晚建模；第 2 天编程+结果；第 3 天写作+收尾】。要改就说，没意见回复"过"。

**用户:** 过。

**智能体:** 用户画像：分析你去年论文 → 弱项是**建模偏简单、没固定随机种子、摘要弱**。**展示**【本赛关注点：建模手注意模型深度（但也提醒"以稳为主"）、编程手固定随机种子、论文手摘要写好】。这是**软引导**，非严格规定；**若你觉得会拖慢，我随时回调**。同意吗？

**用户:** 同意。深度注意下，但别为了深度超时。

**智能体:** 记下"以稳为先、深度适度，赛中回调"。环境（Python 依赖+目录）、分工模式 **混合**、运行模式 **full** 都按默认，**展示**【这些默认】。OK 吗？

**用户:** OK。允许开 VSCode。

**智能体:** **阶段闸门**：Phase 0 全部产出**展示一遍**（Profile/里程碑/画像/环境/协作）。**窗口**：是否通过进入 Phase 1？

**用户:** 通过。

## 三、Phase 1 · 题目剖析与文献集结（按论文写作顺序）

**智能体:** 进入 Phase 1。第一步 **问题重述**（直接帮你写论文开头）。**展示**一段理解：
> 本题要求结合某市共享电单车的骑行、还车、时段、点位数据，围绕"运营质量评价、需求预测、调度优化"三方面建模，交付评价结果、分时分区域需求预测、可执行的调度方案。核心是评价现状 + 给出可落地的改善建议。
**窗口**：对吗？要补充/纠正吗？

**用户:** 概括得对。写"问题重述"时把"数据缺失"也提一下。

**智能体:** 好，我会在问题重述里注明部分时段数据缺失、需插补。（**执行你的意见**）

**智能体:** 下一步 **问题分析**（标"模型/算法/方向/难点"）。**展示**：
- 小问1 评价：**评价类**，可用熵权-TOPSIS / AHP-TOPSIS；方向=客观+可解释；难点=权重来源与指标方向。
- 小问2 预测：**预测类**，可用时序(Holt-Winters)/聚类+时序/随机森林；方向=分区域分时段；难点=部分时段缺失、无稳定周期区域。
- 小问3 优化：**优化类**，可用网络流+最短路径/遗传·蚁群；方向=满足需求下最小化成本；难点=规模大时近似解。
**窗口**：要补/改吗？

**用户:** 小问2 时序怕数据太少不准，先聚类再预测。

**智能体:** 记下"小问2 先聚类再分时序"，无周期区域回落简单回归。（**执行你的意见**）

**智能体:** 下一步 **候选方向**（≥2 方法族 + tradeoff + 反驳清单）→ 你决策。**展示**：小问1 先给"熵权+TOPSIS / AHP+TOPSIS"（**同一族**，被查思路拦下，补跨族 PCA+TOPSIS）。**窗口**：你选哪个？

**用户:** 小问1 用熵权+TOPSIS（好解释、稳）；小问2 聚类+时序；小问3 网络流+启发式。要不要做可行性试点？

**智能体:** 小问3 候选差异明确，不算"优劣难分"，我建议**不做**试点（省时间）。同意吗？

**用户:** 行，不做。

**智能体:** 下一步 **文献检索 + 三查两证**。**展示**：查真实（1 篇无法验证标 `pending`，不进引用，列"待你复核"）；查贴合（剔 2 篇无关，保留给 High/Medium/Low）；证据分级（小问3"调度效率"为推断 → INFERRED，用限定语）。**窗口**：那篇 `pending` 你能确认来源吗？

**用户:** 那篇是知网张XX、2022，你按这个去核。

**智能体:** 好，标 `verified`。（**执行你的意见**）

**智能体:** **阶段闸门**：Phase 1 全部产出**展示**（问题重述/问题分析/方向确认/文献矩阵/真实性复核）。**窗口**：是否通过进 Phase 2？

**用户:** 通过。

## 四、Phase 2 · 分角色攻坚（以小问1 为例）

**智能体（建模手）:** 小问1 用**熵权法 + TOPSIS**。**展示**规格书要点：假设（指标方向已核/极端值预处理/样本充足）、数学形式（`w_j=(1-E_j)/Σ(1-E_k)`、`C_i=D_i^-/(D_i^++D_i^-)`）、参数（指标方向/归一化）、达标判据（权重非极端、排序与数据一致）、反驳清单（高相关/极端值→失真，退路 PCA+TOPSIS）。**窗口**：决策吗？

**用户:** 可以。用这个。

**智能体:** 好。规格书贴 `03_建模思路/model_spec_q1.md`，**展示**。**窗口**：确认后交编程手？

**用户:** 确认。

**智能体（编程手）:** 按**混合分工**（我搭骨架+跑+调 bug，核心你写）。跑通了骨架程序。**展示**结果：

| 区域 | 贴近度 C | 排名 | 主要短板 |
| --- | --- | --- | --- |
| A | 0.72 | 1 | 周转率一般 |
| B | 0.61 | 2 | 潮汐失衡 |
| C | 0.45 | 3 | 投诉率偏高 |

**窗口**：可信吗？要调吗？

**用户:** 先看下 B 区为什么低。

**智能体:** B 区主要是**潮汐失衡**（早高峰还车难）。另定位到**实现问题**（归一化符号 bug）已修。**窗口**：可接受？

**用户:** 行。

**智能体:** 小问2 编程出现**季节项不收敛**（异常）——判定**模型问题**，**回环建模手**：该区域无稳定周期 → 建模手同意**重开方向**改简单回归。已记录。

**智能体（论文手）:** 对照 `references/paper_structure_reference.md`（优秀结构）写小问1"模型建立+结果分析"。**展示**（示意）：
> 为量化评价，构建使用率、周转率、潮汐失衡度、投诉率等指标体系，用熵权法定客观权重、以 TOPSIS 算贴近度排序。结果显示 B、C 偏低，短板集中在潮汐失衡与投诉率。**由结果可推断**失衡点位应为调度优化优先对象……
**窗口**：结构/语气 OK 吗？

**用户:** 可以。"调度优先对象"那句没依据吧？

**智能体:** 有依据——来自小问1 的排序（INFERRED，已用"由结果可推断"限定）；等小问3 出来补量化支撑。**窗口**：还改吗？

**用户:** 不改。

**智能体:** **阶段闸门**：所有小问完成并**展示**（规格书/结果/论文片段）。**窗口**：是否通过进 Phase 3？

**用户:** 通过。

## 五、Phase 3 · 汇总收尾

**智能体:** 进入 Phase 3。先**摘要**（四段式）。**展示**：
> 针对某市共享电单车运营质量，本文构建"评价—预测—调度"框架：用熵权-TOPSIS 识别潮汐失衡与投诉率短板；结合聚类与时序分区域分时段预测，对无周期区域用回归修正；基于需求预测构造网络流+最短路径调度方案。结果表明方案能在满足需求下降低调度成本……
**窗口**：OK 吗？有想突出的数值？

**用户:** 挺好。把"降低调度成本"补个具体值。

**智能体:** **清醒纠偏**：正文目前**没有量化**成本对比，摘要写具体值不实。建议要么**补成本对比表**，要么摘要不写具体数字。你选？

**用户:** 你补表。

**智能体:** 好，补表+摘要对应。**窗口**：AI 声明，今年条款要附。**先问你宽泛还是紧凑？**

**用户:** 紧凑。

**智能体:** **展示**（紧凑）：
> 本作品由团队成员独立完成核心建模、编程与写作，AI 仅用于部分辅助（资料检索、调试建议、语言润色），全部内容已由团队复核确认。
（如实 + 突出人类核心）

**用户:** 可以。

**智能体:** **综述检查 + 提交清单**：假设一致✅ / 未引用结论（补成本表）✅ / 图数据对应（图2 单位已补）✅ / 敏感性（小问3 做±10%扰动）✅ / 引用 ↔ `.bib` 一一对应✅ / 无"推断写成实测"✅。**展示**完整 Checklist。**窗口**：要改吗？

**用户:** 没有。

**智能体:** **成长报告**（每次必写）：做好=三问用不同方法族、没硬套模型；待改进=摘要写晚致返工、前期指标核校耗时；下次=摘要最后写、先固定随机种子、每个小问先列≥2跨族候选。**展示** + 回写 `user_profile.md`。

**用户:** 好。

**智能体:** **收尾问询**：工程包已整理成 `00~06` + `_mmc_internal`，并提醒"3 天时间 / PDF 提交 / AI 声明已附"。**窗口**：**是否收尾 / 确认提交？**

**用户:** 确认提交，收尾。

**智能体:** 收尾完成。辛苦，下次我会直接读 `user_profile.md`，从你的成长点接着带。

## 附：工作模式对比

| 维度 | **A 仅协助（秘书协助）** | **B 全权代理（秘书代笔）**（演示用） |
| --- | --- | --- |
| 谁做实质工作 | **用户成稿**（skill 出材料+校对） | **skill 代写**（用户监督） |
| 智能体动作 | 出文献/候选+tradeoff/提纲/模板/代码骨架/图，供用户用；用户需要时提供段改建议/核查 | 写/建模/编程，每步**展示**+**留窗口**，关键决策点必确认 |
| 用户 | 作者，亲自写/建模/实现 | 监督者，全程观察+给指导意见 |
| 交付 | 材料包 + 校对意见 | 完成稿 + 过程留痕 |

> **不变量**：两种模式都满足"完成→展示→用户意见→执行"、用户全程知情；区别在**谁做实质工作**（用户成稿 vs skill 代写），而不是"是否让用户看到"。

### 协助模式小演示（秘书出材料，用户成稿）

**用户:** 帮我准备小问1（评价）建模需要的东西。
**秘书（A 协助）:** 好，我不动手写，先给你备——① 文献整理（几篇参考+方法出处+贴合度）；② **方案候选+tradeoff+反驳清单**（熵权-TOPSIS / AHP-TOPSIS / PCA+TOPSIS，各给优缺点/风险/推荐）；③ **提纲**（该节每段写什么）；④ **代码骨架**（已运行通过、可复现）；⑤ 一段约 200 字的**参考语气片段**（不是最终稿）。
**用户:** （自己建模、自己写正文）
**秘书:** 我帮你**核查**这段：参数量纲、指标方向、引用规范、公式是否超宽、有没有"把推断写成实测"。
**用户:** 这段我自己改成这样，你看行吗？
**秘书:** 可行。有一处语气偏绝对（"显然"），建议改克制些。是否要我改？——最终**成稿主导权在你**，我交付的是**材料包 + 校对意见**。
