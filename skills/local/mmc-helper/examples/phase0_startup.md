# 示例 · Phase 0 立项（startup_agent · 含预准备）

> 说明：以下为**示例演示**，数据与结论为虚构，用于展示 skill 的运转效果与**人机交互**。真实使用时按实际输入填写。

> **示例中的技术栈（语言、编辑器、库）仅为举例**——实际以你在 Phase 0 确认的环境为准；
> 换成 MATLAB / R / LINGO / SPSS 或别的编辑器，流程与留痕要求完全相同。
> 通用适配见 `references/tool_and_env_guide.md`。

## 用户输入
> "我们参加国赛，这是题：某市共享电单车运营，给了各区域骑行、还车、时段、点位等数据。要我们评价运营质量、预测需求、给出调度优化方案。比赛 3 天。以前我建模爱用简单办法，这次想做得深一点。"

## 第零步 · 预准备（人机协同开场）
> 🤖：先确认两件事。① **工作模式**：A) 仅协助（我每步做完停下等你意见）；B) 全权代理（我更自主，但**每步展示+留窗口**，你全程知情）。
> 🧑：选 B 全权代理。
> 🤖：② 请给我**赛题/通知原文、团队分工、编程环境**；有**历史论文/目标优秀论文**也一并给我。③ 写作侧：**你有没有针对这道题的目标优秀论文/获奖作品**？有给我，没有我用内置获奖论文学习库先学。
> 🧑：（给赛题 pdf + 通知 + 去年论文 + 一篇类似获奖论文）

## 第一步 · 确认竞赛 Profile + 原文提取
- 解析通知原文：`CN_CUMCM`、3 天、需提交 PDF 论文、**今年要求附 AI 使用说明**、禁止某些数据源。
- 写入 `state.competition_profile = CN_CUMCM`（比内置默认更准）。
- **展示**【时间盒/格式/AI 声明/禁止项】→ **留窗口**：用户无异议。

## 第二步 · 确认分工与里程碑（timeline.md）
- 分工：A 建模、B 编程、C 写作。里程碑：第 1 天上午剖析+方向，下午至晚上建模；第 2 天编程+结果；第 3 天白天写作，晚上收尾。
- **展示**【里程碑】→ **留窗口**：用户通过。

## 第三步 · 环境与目录初始化
- `requirements.txt` + `00~06` + `_mmc_internal/` 骨架。**展示**→ **留窗口**：用户过一眼，无异议。

## 第四步 · 分工模式 + 运行权限 + 运行模式
- 用户选 **混合**；确认**允许打开 VSCode、在我的环境跑代码**；运行模式 **full**（时间稍紧，可中途切 light）。
- **展示**【分工=混合 / 权限 / full】→ **留窗口**：用户确认。

## 第五步 · 用户画像（软引导）
- 用户上传去年论文 → 我分析：建模偏简单、没固定随机种子、摘要较弱。
- 更新 `user_profile.md`，产出**本赛关注点**：建模手注意模型深度（但也提醒"以稳为主，别为深度而过度复杂"）；编程手固定随机种子；论文手摘要写好。
- **软引导、非严格约束，赛中回调**。**展示**【画像+关注点】→ **留窗口**：用户补充"以稳为先，深度适度"。

## 产出留痕
- `state.json`：`{competition_profile:"CN_CUMCM", interaction_mode:"B", run_mode:"full", collab_mode:"mixed", phase:0, current_role:"startup"}`
- `timeline.md`、`MMC_Journal.md`、`00_用户画像/`、`user_profile.md`。

## 阶段闸门（人机协同）
- 🤖 **展示** Phase 0 全部产出，问"是否通过进入 Phase 1？" → 🧑 通过。

## 这里体现的原则
- **人机协同**：每步"完成→展示→留窗口→用户意见→执行"；全权代理 B 也每步给窗口，用户全程知情。
- **主导权在用户**：Profile / 分工模式 / 里程碑都是用户确认。
- **清醒纠偏**：用户"想做得深一点"——我提醒"以稳为主，别为深度而超时/不可解释"，作为软引导而非一味迎合。
- **获奖论文学习库**：主动问用户是否有目标优论，有则聚焦学习结构。
