# 示例 · Phase 1 题目剖析与文献集结（按论文写作顺序 · 三查两证）

> 说明：示例演示。沿用"共享电单车调度"题。Phase 1 **输出贴合论文开头**（问题重述→问题分析→思路/文献），每步"完成→展示→留窗口→用户意见→执行"。

## 第一步 · 问题重述（→ 论文"问题重述"）
> 🤖 展示一段话理解题目，等用户确认。

本题要求结合某市共享电单车的骑行、还车、时段、点位等数据，围绕"运营质量评价、需求预测、调度优化"三方面建模。需交付：① 服务质量评价；② 分区域/分时段需求预测；③ 可执行的调度投放方案。核心是既评价现状，又给出可落地的改善建议。**窗口**：用户确认"思路对"。

## 第二步 · 问题分析（→ 论文"问题分析"）
> 🤖 逐问拆解，标出"模型/算法/方向/难点"，等用户补充。

- **小问 1（评价）**：评价运营质量 → 属**评价类**，可用**熵权-TOPSIS / AHP-TOPSIS**，方向是"客观+可解释"，难点在**权重来源与指标方向**。交付：区域质量排序。
- **小问 2（预测）**：预测需求 → 属**预测类**，可用**时序（Holt-Winters）/ 聚类+时序 / 随机森林**，方向是"分区域分时段"，难点在**部分时段缺失、无稳定周期区域**。交付：需求曲线。
- **小问 3（优化）**：调度优化 → 属**优化类**，可用**网络流+最短路径 / 遗传蚁群**，方向是"满足需求下最小化成本"，难点在**规模大时近似解**。交付：调度方案。
> **窗口**：用户对小问 2"数据缺失"补充意见，我记下用插补处理。

## 第三步 · 候选方向（≥2 方法族 + tradeoff + 反驳清单）→ 用户最终确定
> 🤖 展示候选 + tradeoff + 反驳清单，等用户选定。

- 小问 1：最初给"熵权+TOPSIS / AHP+TOPSIS"（**同一族**），被**查思路**拦下 → 补跨族候选（PCA 降维+TOPSIS）。**窗口**：用户选熵权+TOPSIS（好解释、稳）。
- 小问 2：先聚类再分时序（Holt-Winters）；无稳定周期区域回落归——**窗口**：用户认。
- 小问 3：网络流+最短路径 + 启发式校验。**窗口**：用户认。**可行性试点验证**：不需要（不算优劣难分）。

## 第四步 · 文献检索 + 三查两证
> 🤖 检索 + 核对真实性/贴合度，展示文献矩阵与待复核项，等用户意见。

- 检索关键词：共享单车调度、时序预测、熵权-TOPSIS。
- **真实性凭证**：每篇核对可验证标识；1 篇无法验证标 `pending`，不进正文引用，列"待你复核"。
- **贴合度过滤**：剔除 2 篇无关；保留篇目给 High/Medium/Low。
- **证据分级**：小问 3"调度效率"为推断 → INFERRED，用限定语。
> **窗口**：用户确认那篇 `pending` 属实并补充来源 → 我标 verified。

## 第五步 · 阶段闸门（人机协同）
> 🤖 **展示** Phase 1 全部产出（问题重述/问题分析/方向确认/文献矩阵/真实性复核），问"是否通过进入 Phase 2？" → 🧑 通过。

## 产出留痕
- `01_题目剖析/`（问题重述 · 问题分析 · 方向确认 · 文献真实性复核）、`02_文献资料/`（参考文献.md + refs.bib + 文献矩阵）。

## 这里体现的原则
- **按论文顺序产出**：问题重述 → 问题分析 → 思路/文献，直接喂给论文开头几节。
- **人机协同**：每步展示 + 留窗口，用户可补充/否决（如对低缺失、对 pending 文献）。
- **三查两证**：查思路（跨族+反驳）、查真实（验标识/标 pending）、查贴合（剔无关）、证据分级（INFERRED 用限定语）。
- **清醒纠偏**：小问 1 我建议"好解释+稳"，未盲目追求复杂。
