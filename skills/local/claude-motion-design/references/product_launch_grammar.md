# product_launch_grammar.md — AI 产品发布片六幕叙事语法

> 来源：Firefly AI Pet 45s→60s 升级复盘。45s 版验证了 SVG Motion Engine，
> 但结构是"技术架构展示"（核心→运行时→能力→交互的**功能罗列**）。
> 升级为产品发布片的关键：给架构一个**情感弧线**——先有问题，后有回应。

## 一、六幕结构（60–120s AI 产品发布片骨架）

| 幕 | 名称 | 时长占比 | 画面责任 | 观众情绪 |
|---|---|---|---|---|
| P Problem | 问题 | 12–18% | 旧世界的碎片化：散落的笔记/提醒/工具窗口，各自为政，灰色暗淡 | "这就是我的日常" |
| C Connection | 连接 | 12–15% | 一个光点穿越碎片、开始汇聚——**第一次出现琥珀色**；碎片被点亮 | 注意力被抓住 |
| M Memory | 记忆 | 12–15% | 数据库/时间线/节点网络形成——"它记得你"，涓流包持续读写 | 被理解的暖意 |
| A Agent Capability | 能力 | 18–25% | Skills/MCP/执行状态机全速运转——能力展示**但以服务动作呈现**（不是功能列表） | "它真的能做事" |
| C Companion | 陪伴 | 15–18% | Avatar 与用户对话/眨眼/微笑——从工具到伙伴的情绪转折 | "这是有生命的" |
| B Brand | 品牌 | 8–10% | 全部元素汇聚成品牌锁定，tagline 收束 | 记住了名字 |

节奏：C 幕末尾开始加速（Connection→Capability 的推进感），A 幕峰值，C 幕收稳，B 幕锁定。

## 二、叙事规则

1. **Problem 必须具体**：不要"信息过载"这种抽象词——画面上是 6 个互不相连的碎片卡片
   （提醒/笔记/日程/搜索…），各自闪烁、各自暗淡，中央无人。观众认出的是自己的桌面。
2. **琥珀色 = 产品的到场**：P 幕全片禁用品牌色（冷灰/青灰）；C 幕第一颗光点出现时
   品牌色才第一次进入画面——色彩本身即叙事。
3. **每次能力展示都从"用户收益"的动词开始**：PLAN→"它替你安排"，MEMORY→"它记得"，
   SKILLS→"它学会"。器件标签保留但降为次要层级。
4. **Companion 是情绪峰值**：Avatar 出场前所有元素都是几何的；Avatar 第一次眨眼/微笑
   是全片唯一的"生命时刻"，此前积攒的所有连线此刻汇入它的触角。
5. **Brand 是收束不是介绍**：品牌卡只做"确认"，不传递新信息。tagline ≤ 8 字。

## 三、SVG 原语选型（详见 svg_product_primitives.md）

- 碎片卡片（P）：`FragmentCard` — 互不相连、随机微颤、低饱和；
- 光点穿越（C）：`WanderLight` — 单光源贝塞尔巡航，触发的碎片点亮；
- 记忆网络（M）：复用 `Memory` 缸体 + 节点网络 + 涓流包；
- 能力矩阵（A）：复用 Skills 芯片网格 + MCP 总线 + 执行状态机；
- 陪伴（C2）：复用 `Avatar` + 对话气泡（spring 滑入 + 打字点）；
- 锁定（B）：复用品牌汇聚（节点→辉光球→字标）。

## 四、与 TJU 历史片的语法差异

| 维度 | TJU 历史片 | 产品发布片 |
|---|---|---|
| 因果链 | 时代→人→文书→物（**证据链**） | 问题→连接→记忆→能力→陪伴（**价值链**） |
| 画面主体 | 档案照片物证 | 纯 SVG 器件与角色 |
| 文字角色 | 年份/名字（确认） | 收益动词/对话/品牌（服务承诺） |
| 情绪 | 庄重/缅怀/自强 | 被理解→被赋能→被陪伴 |
